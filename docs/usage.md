# 使用指南

Windows x64（64 位）上的 Codex 请求分析与无损传输压缩工具。双击一个 EXE 即可使用，无需 Python、管理员权限或额外的代理程序。

程序使用 Codex 的 provider 配置接入本机 HTTP 出口，不修改 Codex 的安装文件或设置页。请求继续使用原有认证、公司网络代理和 TLS 校验。程序是独立的第三方工具，不属于 OpenAI 官方产品。

本项目不开发或安装 Codex 补丁，不替换核心、注入代码或直接修改会话历史。会话名称和归属依据原生记录及明确的请求元信息；Token 优先采集真实上游响应，缺失时才只读 Codex 已有记录。预测保护使用的上报值与真实用量分开保存，界面统计使用真实用量。

## 使用

1. 从 [Releases](https://github.com/qzz1008-glitch/codex-request-optimizer/releases) 下载正式主程序 **`CodexPacketInspector.exe`**，双击安装或升级。一个 EXE 已内置前端、后台和首次安装所需的固定入口，无需 Python 或管理员权限。其他发布附件仅为 README、项目许可证和第三方许可证，不需要另下升级包。
2. 安装或升级完成后自动打开优化器，也可从开始菜单打开。确认接入后，后台检测用户配置及独立 profile 的 HTTP provider，备份后统一接入默认 47844 入口。Codex 账户连接使用 `OpenAI` 名称和稳定的默认 provider；旧会话标识、认证、附加请求头及各自上游保持对应。
3. 首次接入或更改入口端口后，**重启 ChatGPT App 生效**。运行中的聊天可能仍缓存旧出口；固定端口下的后续优化器升级不需要重启 ChatGPT App。

浏览器也可打开 <http://127.0.0.1:47844/>。关闭优化器窗口会保留托盘和中转。设置中的登录启动默认关闭；升级保留已有设置。

## 查看会话与请求

顶栏的“断开 / 接入”开关统一管理主配置、独立 profile 及内嵌 profile 的 provider，与图片模式无关。接入时同步原生请求压缩开关，关闭 Codex 原生 zstd，由本软件按所选等级或自动策略压缩。图片设置只管理工具安装与图片替换，独立识图会话沿用当前连接，无需专用 provider；请求大小保护和图片处理仍由各自设置控制。断开时恢复各自原上游，并明确开启 Codex 原生请求压缩；Codex 账户连接保留 `OpenAI` 名称，API Key 等其他连接不改认证与名称，是否支持原生压缩由 Codex 决定。

首次接入、断开及再次接入均会备份并校验配置，写入失败时回滚本次已写入的文件。新会话使用稳定 provider，旧会话标识保留，不修改历史；断开后再次接入复用对应路由，避免中转转发回自身。重复接入且配置已经一致时无需重启；配置发生变化后按提示重启 ChatGPT App，重启前已有请求继续转发。

左栏按最近更新时间显示会话名称、完整 session_id 和最近请求的输入 Token；原生压缩后的上下文总量估算带 `≈` 标记。启动时先选中最近会话，再加载它的请求；切换会话后，中栏只显示对应请求。图片解析、自动标题等归属明确的辅助请求归入父会话，未识别请求集中在“其他”；普通子任务和独立会话保留各自行，可确认的父子关系以关联线标记。

中栏显示原始包、压缩包和真实输入 Token。原始包是传输压缩前的 JSON 大小；压缩包在传输压缩后、超限保护前测量，因此可能不同于最终上传大小。右栏的压缩方式和等级也对应这一阶段；旧摘要记录缺少对应信息时显示“—”。实际发起过容量不足重试的请求会有整行标记，详情只显示自动重试是否触发。

右栏提供“请求信息 / 大小构成 / 请求正文 / 变化明细”四个页签。请求信息按适用情况显示请求与响应、会话信息及图片信息。请求正文默认折叠内部结构，支持关键词搜索、JSON 路径定位，以及通过右上角按钮下载脱敏 JSON。三栏支持选中文字复制，实时刷新和排序时保留仍然有效的选区。

### 趋势图

顶部居中的“记录 / 趋势”切换会把三栏替换为左侧会话列表和右侧上下两张曲线图，返回时保留会话和请求选择。右上显示包大小，沿用请求列表中“压缩包”的口径；右下显示输入 Token。默认范围为最近 **1 小时**，可切换至 6 小时、24 小时或全部保留记录。

两图共用实际时间轴和会话颜色。左侧可搜索会话，悬停会话或曲线时联动高亮两图中的对应曲线；悬停节点时定位同一请求。上图提示显示压缩包大小和时间，下图显示输入 Token 和时间。功能标记中，菱形表示预测保护，三角表示超限保护，空心圆表示自动重试，方形表示上下文压缩；标记重叠时优先显示超限保护，其次显示上下文压缩。

自动标题、消息建议、会话索引和预热请求不混入曲线；上下文压缩请求有真实包大小时在上图展示，不推测其 Token 用量。缺失数值跳过取点，连接前后已知点。页面可见时约每 2 秒刷新，最多显示最近 12,000 条已保留请求；“全部记录”仍受此数量限制和记录保留设置约束。

### Token 用量

优先采用真实上游响应中的输入、输出 Token，与请求大小保护开关无关；旧请求缺少响应用量时，才只读匹配的 Codex 本机 `token_count` 记录。不读取原生窗口上限，不显示窗口占用百分比，也不使用预测保护上报的合成用量。无法匹配、尚未写入或只能估算时明确标注，不用相邻请求的用量代替。上下文窗口和自动压缩阈值仍可在设置中独立调整。

## 两种升级方式

- **本地代码升级**：运行 `python -m scripts.build_inspector --output-dir release/<新的目录名>`，将生成的 `CodexPacketInspector.exe` 交给用户。EXE 内置这一次构建的代码，双击后同时升级已经运行的后台和优化器桌面窗口。
- **GitHub 在线升级**：v0.6.14 及更新版本可在设置的“版本与升级”中点击“检查更新”→“立即升级”，直接下载正式主程序。下载使用 GitHub API 返回的大小和 SHA-256 校验，验证通过后使用主程序内置的升级流程，自动关闭旧界面并打开新版。更早的只识别旧升级文件名的版本，请手动下载并运行正式主程序。

本仓库及 Release 均为公开，下载与检查更新无需 GitHub 登录。若使用私有更新源，需要相应访问权限，并通过 GitHub CLI 登录，或在启动环境中设置 `GH_TOKEN`。凭据只在内存中使用，不写入源码、发布文件或更新状态。预发布版和草稿不作为自动升级目标。

程序版本分别存放，采集记录与统计始终沿用原数据目录下的同一个 `packets.sqlite`。兼容的历史记录、详情和统计随升级继续可用。

固定入口由主程序以入口模式运行，不再单独构建路由 EXE；入口进程与后台进程共享同一种主程序。每次升级先把新版后台放入带哈希的版本目录，在随机本机端口启动并验证，再将新请求切到新版。已经转发的请求继续由旧后台完成；旧后台排空后退出。正常升级保留入口进程和公共端口，不覆盖正在使用的 EXE，也不重放推理请求。优化器桌面窗口会关闭并重新打开，以加载新版前端。

托盘随当前后台更新，使用与新窗口一致的图标。新版托盘就绪后才交接；旧入口只退出托盘线程，继续转发请求。每次升级同步刷新开始菜单及属于本安装的任务栏快捷方式，并保留登录启动开关、开发版或正式版模式及已有数据。升级后从托盘打开的窗口始终使用当前版本。

旧版本程序及下载副本设有 7 天保护期，每类额外保留最近两个回退副本；仍在运行、排空请求或被桌面窗口使用的版本继续保留。仅清理本程序管理的文件，用户额外文件、开发目录及统计数据库保留。回滚失败时保留已经接管请求的后台，避免错误清理中断中转。

**首次从旧版迁移**需要等旧中转没有活动请求，再交接公共端口一次，存在短暂连接空隙；等待 60 秒仍忙碌则取消，不强制中断请求。新版就绪或切换验证失败时保留或恢复旧后台。程序与配置备份位于数据目录的 `upgrade-backups`；版本文件、入口状态和在线下载同样保存在本机数据目录。

`CodexPacketInspector.exe` 保留旧文件名以兼容现有快捷方式。安装后的固定路径运行入口，新版应用在 `bin/versions/<sha256>/` 下；不要用普通应用 EXE 手动覆盖固定入口。命令行安装和升级脚本也只调用 `CodexPacketInspector.exe`。

provider 配置变更由同一中转服务检测并热加载，无需重启中转。恢复原配置会关闭自动接管，避免被后台再次接入；“接入 Codex”可重新开启。自定义非 HTTP 传输、命令行覆盖配置的出口不在自动接管范围内。

“设置 → Codex 接入 → 入口端口”可保存 1024–65535 范围内的端口，并分别显示当前端口和待生效端口。配置独立保存在数据目录的 `entry-port.json` 中。保存不会重启或中断当前中转，也不会立即改变 provider 地址；支持此配置的入口服务下次启动时读取新端口，再统一更新 provider。重启 ChatGPT App 生效。固定端口下的日常升级不需要重启 ChatGPT App。

源码服务未指定 `--port` 时读取上述配置，默认 47844；显式 `--port` 优先，`--port 0` 仍用于隔离验证。旧版 EXE 不识别新增的端口配置，需要入口升级后应用。

迭代构建和测试使用独立目录、随机端口、临时配置，不停止当前中转。需要命令行升级时，可运行 `CodexPacketInspector.exe --upgrade`；源码开发者也可用 `scripts/windows/update_inspector_service.ps1 -SourceExecutable <正式版 EXE 路径>`。`-Port` 可省略，由升级器读取当前入口。脚本不提供强制结束进程的升级方式。

## 设置

点击右上角齿轮打开设置。修改后统一点击底部“保存”，左下角显示各步骤的处理结果；失败时保留未保存项，重试只处理尚未完成的步骤。“恢复”撤销未保存修改，不是恢复所有默认值。需要重新加载 Codex 才能生效的配置会在保存后提示。

- **开机启动**：安装版在当前用户登录 Windows 后于后台启动，从托盘打开窗口。新安装默认关闭；升级保留已有开机启动状态。关闭此选项只取消后续自动启动。
- **容量不足重试**：默认关闭，重试次数和等待秒数均可设为 1–99，默认 15 次、30 秒。中转只为明确容量错误补充 `Retry-After`，由 Codex 原生等待、重试；文字与工具调用继续实时显示，中转不自行重发请求。上游要求更久时遵循上游。次数通过标准 provider 配置设置，也适用于其他可重试流错误，修改后需重新加载 Codex 配置，当前生成步骤不会实时更新；重启 ChatGPT/Codex 可确保加载。开关在新请求开始时决定是否介入，已开启请求的后续错误使用最新等待时间；关闭或取消接入会恢复原有重试配置。

- **图片解析**：提供“原生 / 禁用 / 优化”三种模式，默认原生。选择优化后，EXE 备份标准配置、禁用原生 `view_image`，并安装和注册独立 stdio MCP 图片工具；已有用户自定义的独立工具会保留。工具由 Codex 启动，在独立会话中识图，只返回文字，主请求使用图片路径。EXE 负责安装、卸载和升级，工具不使用 EXE 的 HTTP 接口或 Hook。选择原生会卸载本程序安装的工具及注册、恢复原生 `view_image`；选择禁用关闭两种入口。配置变化后重新加载 ChatGPT App，安装或保存失败会自动回滚，不修改 Codex 程序文件。

  新用户无需复制其他人的工具目录，也无需为这个工具另装 Python、Node.js 或 MCP 插件。服务已随 Windows 安装包提供；启用时自动查找 PATH 或 Codex 桌面版缓存中的官方 CLI，并建立独立识图配置。找不到 CLI 时提示补装，原配置不变。Codex 桌面版升级导致 CLI 路径变化时，内置识图服务会重新定位。

  设置中的“图片保存路径”默认使用中转数据目录下的 `image-attachments`，并显示完整路径。可输入自定义绝对目录，或点击“使用默认目录”填回默认值，再点击底部“保存”。保存时创建并检查目录的写入权限；成功后用于后续保存，原目录文件保留，失败不改变当前目录。

  启用后，用户消息中的内嵌图片在本机保存为内容去重的附件，上游主请求只收到原问题与图片路径。模型按任务调用 `isolated_vision.analyze_image`，由 `isolated-vision` profile 启动独立、临时的 Codex 识图运行，仅返回文字。专用 provider 保留原有认证方式，并使用内部标记避免识图请求被再次去图；内部标记不转发上游。历史中重复携带的图片在每轮主请求中重新替换，超限摘要也只接收替换后的请求。外部 URL、文件 ID 或不支持的位置不能安全转换时明确报错，不静默上传原图。

  系统临时目录中的 `codex-clipboard-*` 图片会复制到 `%TEMP%\CodexRequestOptimizer\`，当前请求与图片信息改用新路径，原文件保留。这份缓存最多 ≈268.44 MB，在后续处理图片时清理超过 7 天未使用的副本；复制失败或缓存已满时保留原路径。其他目录及普通用户文件不迁移。

  Codex 发给本机中转的原始请求以及本地会话附件仍会含图；本功能只修改中转发给上游的副本。详情页区分原始抓包与实际去图状态。附件单张上限 52.4288 MB，独立识图上传超过 409.6 KB 时尝试本机缩图；自有附件缓存上限 ≈268.44 MB、未使用 7 天后按需清理。独立解析会产生额外模型请求，程序自带 MCP 工具每个连接会话最多调用 24 次。大图缩图可能损失细节。

- **传输压缩**：顶栏处于“接入”状态时生效。手动压缩等级为 1–17，默认 3，升级保留已保存的等级；可比较各等级的压缩大小与本机耗时估算。
- **上下文**：用数字输入有效上下文及自动压缩阈值，单位为 k tokens，各项可单独选择“默认”。保存前校验并备份 Codex 配置，需要 Codex 重新加载后生效。
- **请求大小保护**：新安装默认关闭，已有选择保持不变；启用后同时提供预测保护和超限保护。“压缩包上限”使用 KB，1 KB = 1,000 字节，默认 1,000 KB，即 1,000,000 字节。按传输压缩后的上传大小判断，距离上限 50,000 字节时触发预测保护，超限时触发超限保护。同一会话复用摘要时仍按替换前大小判断，原始请求回到上限内时清理摘要缓存。
- **按包大小自动压缩**：默认关闭，开启请求大小保护后可启用，在接入状态下生效。先检查当前主请求在图片改写、摘要替换前的未压缩正文：小于上限的 90% 时不额外压缩，已有 zstd 包保持原样。其余请求没有档位记录时，原始包小于 1,500 KB（1,500,000 字节）选 1 级，达到该值选 17 级；此初次阈值固定，不随用户上传上限缩放。已知会话从小包增长后先用 1 级，摘要处理前的压缩包达到上限的 90% 后，下一条同上游、同会话的主请求升到 17 级，本条不重复压缩。17 级保持锁定，即使压缩包变小也不降档；只有后续主请求的未压缩正文回到上限的 90% 以下才解除，通常发生在原生上下文压缩之后。原生压缩请求本身、预热、记忆、标题、建议、图片解析、会话索引和工具搜索不改变主请求档位，子任务独立计算。1 级和 17 级均正常执行预测及超限保护；初次阈值只降低快速档触发保护的概率，不保证完全避免。已有 zstd 的快速档不重压，17 级仅在重压结果更小时替换；传输层不再临时升档。每个正文最多尝试一个等级。档位独立保存在本机数据库，不受采集开关、记录清理、服务重启或时间间隔影响。缺少档位时，读取同上游、同会话上条可用主请求的元数据恢复；概要和详情均可使用，不依赖请求正文。优先使用已记录的下一档位，旧记录按摘要替换前包大小和已知高压缩状态判断，均无可用信息时才使用初次阈值。自动模式下手动等级置灰，关闭后恢复原来的手动等级；关闭请求大小保护也会关闭自动模式并清空活动档位；再次启用时仍可从保留的请求元数据恢复。
- **记录设置**：默认最多保留 ≈536.87 MB、2,000 条请求记录。存储上限可设为 16.777216–8,589.934592 MB，条数上限可设为 10–20,000 条。左栏底部显示“记录占用 / 存储上限”和当前请求数，清理规则见下方“记录与存储”。

预测保护达到大小条件后，需等待完整响应提供有效 Token 用量才能完成改写。等待时显示“等待响应”，响应中断等原因导致未改写时显示“未完成”；真实用量本就达到保护值时显示“已满足”。超限保护生成摘要成功，不等于预测保护已完成。

请求详情中的“自动重试”只显示“已触发 / 未触发”，缺少采集记录时显示“暂无记录”。计划重试但在等待时取消或关闭开关，不计为实际重试；右栏、列表和趋势图均以实际发起过重试为准。右栏不显示请求时设置、停止原因、结果或日志下载入口。

响应元数据不会提前结束重试检测；输出条目、推理或工具调用出现后不再重放。未知且无法判定的事件保持原样转发并写入诊断原因。仍只重试明确的容量错误，HTTP 403、413、普通 5xx 和连接异常不会新增重试。

后台诊断日志记录本次请求各次尝试的时间、HTTP 状态、错误代码、等待计划、检测停止位置，以及向 Codex 发送响应头和首批正文的时间。日志保存在数据目录的 `retry-diagnostics.sqlite`，不随抓包正文删除；暂停正文采集时仍记录这些诊断元信息。发生重试或异常的记录最多保留 30 天，普通成功记录保留 24 小时且最多 2,000 条，总体按 20,000 条、≈33.55 MB 内容预算清理最旧已结束记录，优先清理普通成功记录；正在进行的请求暂不删除，超过 6 小时无更新则标记缺少结束记录。SQLite 文件可保留可复用空间，并在空闲时回收。日志不包含对话正文、工具参数、输出、推理密文或认证头。已清理的抓包仍可按会话查询 `/api/retry-diagnostics?session_id=<session_id>`，再按返回的 `id` 下载 `/api/retry-diagnostics/<id>?download=1`。

传输压缩对 `POST /responses` 生效，包括通过这个接口发送的上下文压缩请求。压缩本身是无损的：解压后与压缩前正文逐字节一致，不重新序列化 JSON。切换配置尚未生效时，已有 zstd 请求仍可正常转发或在新包更小时替换；gzip 和其他未验证端点保留原编码。图片转路径和超限保护是分别启用的处理步骤，不属于无损传输压缩。上游需支持 zstd 请求正文。

分析器只记录经过已配置 provider 的 HTTP 请求，不接管其他应用流量。接入时关闭自定义 provider 的 WebSocket 支持以使用 HTTP。直连上游时，列表显示本工具最终上传正文的大小；当上游是另一个本机出口时，其后续处理后的上传大小无法确定，显示“—”。HTTP 头和 TLS 开销不计入正文大小。

认证头值不保存，已识别的凭据与媒体在浏览副本中脱敏。普通聊天、工具输出仍保存在本机，应按敏感数据管理。转发正文不使用脱敏副本。

## 记录与存储

记录占用是已保存的脱敏请求副本经本地压缩后的大小，加上请求元数据的字节数，与设置中的存储额度使用同一口径。它不包含 SQLite 索引、日志和可复用空间，也不包含图片附件、摘要缓存或独立诊断日志，因此不是整个数据目录的磁盘占用。

服务启动、新增或更新采集记录时检查容量和条数；任一上限被超过，就按请求创建时间从旧到新删除，直到满足两项限制。调低上限后，在后续检查时执行回收。清理不区分已完成、失败或转发中状态，单条记录自身超过容量上限时也不会保留。

删除转发中请求的采集记录不会中断转发，响应完成后也不会重新创建该记录；请求数和趋势图随保留记录更新。启动时会将已停用旧采集模块遗留的未完成记录标记为中断，不重放请求，也不修改 Codex 的原始会话历史。

SQLite 文件可能暂时保留可复用空间，空闲时再回收。独立诊断日志、摘要缓存和图片附件分别按各自的保留规则管理，不随一条请求记录的删除一并清空。

## 超限保护

在设置中启用“请求大小保护”后，此功能作为偶发超出用户配置上限的兜底，默认上限为 1,000,000 字节。原生自动压缩仍负责日常上下文管理；本功能不修改其 token 阈值配置、Codex 核心或本地会话历史。

中转在发送前测量实际编码后的正文。原始请求超限时，将已完成的历史前缀生成交接摘要，保留系统/开发者指令、工具目录和未压缩的新内容。缓存精确的历史前缀指纹和替换结果，后续同一会话继续使用；替换后再次超限则更新摘要。原始请求回到预算内、历史前缀变化或模型/指令/工具配置变化时，旧映射失效。

当前实现沿用 Codex 原生使用的 `/responses` 文本交接摘要协议。摘要调用不提供可执行工具，只有完整完成的文本摘要进入缓存。普通对话达到预测阈值时，只在成功响应的用量字段中将输入 Token 提高到至少 500,000，并同步总数，促使 Codex 下一轮执行原生压缩；实际输入、输出及缓存用量另外保存供界面统计。预测按摘要替换前的上传大小判断，因此首次摘要和缓存命中均不会跳过。原生压缩请求和摘要调用不改写 Token。

摘要请求以当前原生请求为模板，完整继承 `reasoning`、`include`、客户端扩展及未知字段，减少原生协议新增字段时的适配工作。仅替换摘要输入，移除工具执行入口、旧响应续接标识及原回复的格式/长度限制，并设置摘要用途的流式输出、缓存键和请求标记；原始请求对象不被修改。上游拒绝摘要请求时，错误会保留有限长度的脱敏 JSON 原因，便于识别具体不兼容字段。

文本压缩使用原生摘要提示词、原生摘要前缀和 `user/input_text` 消息格式。重组时按照原生规则保留近期用户文本（约 20,000 token，以 UTF-8 字节数除以 4 估算；边界消息保留头尾并标记截断），随后放入摘要，再接上未压缩的原始后缀。旧摘要不作为新的用户指令重复保留。系统/开发者指令、工具目录、AGENTS.md、环境上下文、跨会话通知以及带附件或内部标注的用户消息原样保留；中转不具备原生世界状态和附件处理能力，因此对此采取更保守的保留规则。原生跨会话通知属于独立上下文，不要求对应工具调用；普通工具结果仍需先有对应调用。上下文的原有相对顺序保持不变。

这不是完整的原生压缩：中转只替换上传的历史前缀，不执行原生会话落盘、世界状态重建、压缩钩子或 token 计数重算。正常自动压缩仍交给 Codex。摘要属于有损语义压缩，结构对齐和原文保留不能保证模型永不遗漏事实；过大的必须保留内容会使本次兜底明确失败。

压缩调用和最终请求分别校验上传预算。压缩失败、没有安全的历史切分点，或单条新内容/工具目录自身过大时，返回明确的 `overflow_*` 错误，原推理请求不上传、不重试。并发请求按会话串行准备，成功映射原子保存在数据目录的 `overflow-context.sqlite`，服务重启后可以复用。此数据库包含用于后续上传的摘要原文，独立于脱敏抓包；认证头不写入缓存。开启后只有被替换的 `input` 字段重新编码，其他顶层字段保留原始字节。

已有编码为 gzip/zstd 的正文在替换后按原编码重建。若上游还有其他会修改正文的中转，本工具只能保证自身出口的正文大小，无法保证后续出口大小。

摘要缓存默认在 7 天未使用后过期；成功读取会刷新使用时间。缓存以 256 个会话映射和 ≈67.11 MB 替换内容为预算，超限优先淘汰最久未使用的映射。服务启动和后台每 10 分钟执行检查，即使关闭超限兜底也会清理遗留缓存；读取时也会检查过期。正在准备或转发的请求所引用的映射不参与淘汰，全部映射都在使用时可能暂时超过预算，请求结束后后台继续回收。缓存被回收只意味着需要时重新生成摘要，Codex 原始会话历史不受影响。

摘要库和抓包库均在没有转发请求时检查磁盘空间：空闲页达到 4.194304 MB 且占数据库页数至少 25% 时执行收缩，同时回收可截断的 WAL。清理使用短锁等待和 2 秒操作预算；新请求到达时尝试中止正在进行的收缩，遇到其他 SQLite 使用者则延后重试。摘要库删除时启用 SQLite 的 `secure_delete`，减少空闲页中的旧文本残留。这不等于磁盘介质的安全擦除。清理只操作两个数据库的记录和空闲页，不扫描或删除会话目录、配置、备份或其他文件。状态接口的 `overflow_cache` 提供预算和最近回收结果。

## 停用与移除

1. 如启用过独立图片工具，先将“图片解析”切回“原生”并保存，卸载本程序安装的工具和标准配置注册。用户其他工具文件不会被删除。
2. 在设置中关闭“开机启动”。
3. 右键系统托盘图标，选择“退出程序”。仍处于接入状态时，可选“切换并退出”，恢复原出口后退出，并按提示重启 Codex；“直接退出”保留接入配置，下次发送请求前需要先启动优化器。有活动请求时程序保持运行，等待请求完成后重试退出。
4. 退出后可删除 EXE；如需彻底移除，再删除开始菜单快捷方式和仍保留的 `Codex Packet Inspector` 登录任务。配置备份、采集记录和附件保留在用户目录的 `.codex-packet-inspector` 下，可自行删除。

工具配置默认保存在 `~/.codex-packet-inspector`，Codex 配置默认使用 `~/.codex/config.toml`；支持 `CODEX_HOME`。不会在安装目录写入凭据或修改 Codex App 文件。
